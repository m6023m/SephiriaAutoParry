# Sephiria Auto Parry 0.1.0

저장소: https://github.com/m6023m/SephiriaAutoParry

세피리아 1.0.33 / BepInEx 5.4.23.5용 모드.

옵션 → 게임플레이 → 마법 시전 입력 동작 바로 아래의 **자동 패링 / 가드**. 기본값 켜짐. 변경 즉시 저장.

공격이 닿기 전에 지원 무기의 SubAttackButtonDown(실제 특수공격 입력) 함수를 호출합니다. 기본값에서는 현재 공격·시전·회피를 강제로 취소하지 않으며 입력을 받아들이는 시점은 게임의 원래 규칙을 따릅니다. **자동 패링 강제 캔슬**을 켜면 현재 동작을 게임의 취소 함수로 취소한 뒤 실제 특수공격을 입력합니다. 도의 납도·발도 상태 및 전환은 강제 캔슬 대상에서 제외합니다. 강제 방어 판정, 무적 부여, MP 선차감, 애니메이션 이벤트 선호출은 하지 않습니다. 실제 애니메이션이 여는 방어 시간과 원래 기술의 MP 비용·환급·가드 비용을 그대로 적용합니다.

피격 순서: 게임의 정상 애니메이션 진행에서 특수동작의 시작을 관찰합니다. 피격 처리 전까지 시작하지 못한 자동 입력은 대기 입력만 철회하며, 피해 처리 후 같은 프레임에는 새 자동 입력을 금지합니다. 수동 특수공격 입력이 들어오면 자동 입력 관리 권한을 넘깁니다. 순간적으로 발생한 공격이나 현재 동작이 입력을 받지 못하는 상황에서는 그대로 맞을 수 있습니다. 강제 방어·피해 지연·애니메이션 강제 평가 또는 시간 건너뛰기는 사용하지 않습니다.

감지:
- 공통 ApplyDamage 진입 시 외부 피격원에도 특수공격 입력을 시도. 적/함정/폭발에 공통 적용하며 자기 시스템 피해는 제외.
- 일반/대형 폭발 모듈의 실제 타이머 및 폭발 애니메이션 이벤트 감지. 폭발 반경과 타원 형태를 확인.
- 적 이름이나 훈련장 여부로 제한하지 않고 적대적인 UnitAvatar에 공통 적용. 근거리에서는 Animator2D 및 Unity Animator의 공격 이벤트 시각을 읽음.
- 연결된 함수가 타격/투사체 생성에 도달하는지 게임 IL을 읽어 분류. 비공격 이벤트는 제외하고 결과 캐시. 등록된 delegate와 coroutine도 검사.
- 훈련장 FireTrap 계열은 별도로 실제 발사 애니메이션 이벤트를 읽어 총구 앞 1.25 이내에서 발사 전에 대응.
- 적대 색상의 근접 직사각형 예고(중앙/전방/허수아비), 원형 및 직사각형 범위 예고의 예정 시각·범위.
- 일반 Bullet 투사체의 프레임 간 이동 속도, 실제 플레이어 피격 충돌체와 투사체 충돌체의 위치·크기, 플레이어 진영을 확인하여 충돌 시간을 추정.
- 범위 예고는 약 0.1초, 투사체는 약 0.16초 전에 특수동작 요청. 같은 예고/투사체에는 한 번만 반응하며, 이미 요청 중인 동작에는 중복 입력을 억제합니다.
- 공통 공격 애니메이션 이벤트나 범위 예고가 없는 접촉·즉발 피해, 별도 특수 투사체 및 보스 패턴의 완전한 지원은 보장하지 않습니다. 모든 적/강화/상태 조합의 실전 검증은 아직 안 됐습니다.
- 예고 시간과 실제 타격 시간이 다른 공격, 급회전 투사체, 중간 장애물 등에 대해서는 예측이 빗나갈 수 있습니다. 성공을 강제하지 않습니다.

무기:
- 단검: 실제 특수공격 입력 함수를 호출. 광란 스택이 있으면 퓨리, 없으면 패링. 각 기술의 원래 MP 비용 적용.
- 봉: 기본 방어 특수공격. 투창/특수공격 대체 강화 제외.
- 검과 방패: 실제 특수공격 누름·해제 함수 호출. 도중에 수동 가드를 누르면 자동 해제 권한을 넘김.
- 도: 기본 납도/발도, 튕겨내기, 구름베기. 기본 납도/발도는 원래 비용이 없으므로 MP를 요구하지 않음. 그 외 기술은 원래 MP 비용 필요.
- 봉/방패는 원래 조준 방향과 방어 각도를 적용. 뒤쪽 공격의 방어를 보장하지 않음.
- 싱글 및 호스트 본인 캐릭터 지원. 다른 호스트에 접속한 클라이언트 미지원.

도는 게임의 납도·발도 상태와 실제 입력을 사용합니다. 납도·발도·빠른 발도 전환 중에는 새로운 자동 입력으로 동작을 끊지 않습니다. 일반 납도는 실제 특수공격 키와 같은 토글이므로, 납도 자체가 정상적으로 유지되는 무기는 납도 상태로 남을 수 있습니다.

도 기본 납도·발도는 짧은 원래 방어 시간이 타격 전에 끝나지 않도록 예상 타격까지 0.075초 이내일 때 입력합니다. 예측 오차나 원래 동작의 입력 제한으로 방어에 실패할 수 있습니다.

## 설치 및 설정

1. 게임을 종료하고 BepInEx 5가 설치되어 있는지 확인합니다.
2. Releases의 `SephiriaAutoParry-0.1.0.zip`을 게임 폴더에 풀어 `BepInEx` 폴더를 합칩니다.
3. `BepInEx/plugins/SephiriaAutoParry.dll`과 `BepInEx/patchers/SephiriaAutoParry.Updater.dll`이 있어야 합니다.
4. 옵션 → 게임플레이 → 마법 시전 입력 동작 아래에서 자동 패링과 업데이트를 설정합니다.

설정 파일은 `BepInEx/config/local.sephiria.autoparry.cfg`입니다. 업데이트로 기존 설정을 지우지 않습니다. 제거할 때는 게임 종료 후 위의 플러그인과 업데이트 적용기 DLL을 함께 제거합니다.

## 자동 업데이트

SephPlanner와 같은 흐름으로 시작 시 최신 정식 Release를 확인합니다. 새 버전이 있으면 **업데이트 / 나중에**를 선택할 수 있습니다. 다운로드 중에는 안내를 닫고 플레이를 계속할 수 있으며, 완료 후 재시작 안내가 나옵니다. 옵션의 **자동 패링 업데이트 → 지금 확인** 항목은 좌우 선택으로 수동 확인합니다.

검증된 파일은 다음 게임 실행의 BepInEx 사전 로딩 단계에서 적용합니다. 실행 중인 플러그인을 덮어쓰지 않습니다. 다운로드·검증·교체 실패 시 기존 버전을 유지합니다. 시작 시 확인 실패는 로그에만 남기며 수동 확인 실패는 화면에 표시합니다.

- 정식 `v숫자.숫자.숫자` Release만 사용합니다. 커밋·태그만 올리거나 draft/prerelease를 만들면 자동 업데이트하지 않습니다.
- 파일 크기, SHA-256, 어셈블리 이름 및 버전을 검사합니다. 이는 전송 오류 검증이며 별도의 배포자 서명 검증은 아닙니다.
- GitHub 공개 Releases에서 받으며 토큰을 저장하지 않습니다. 게임 설정이나 세이브를 업로드하지 않습니다.
- 업데이트 자료와 이전 DLL은 `BepInEx/cache/SephiriaAutoParry`에 보관됩니다. 되돌리려면 게임을 종료한 후 원하는 `previous-*.dll`을 `BepInEx/plugins/SephiriaAutoParry.dll`로 복사하고 시작 시 확인을 꺼 주세요.
- 적용기는 프로토콜 1을 지원합니다. 적용기 자체는 자동 교체하지 않으며, 향후 적용기 변경이 필요하면 새 설치 ZIP으로 수동 설치합니다.

## 빌드 및 배포

Windows .NET Framework C# 컴파일러와 합법적으로 설치한 Sephiria/BepInEx DLL을 로컬 참조합니다. 게임·BepInEx·다른 모드의 DLL이나 역컴파일 소스는 저장소 또는 배포 ZIP에 포함하지 않습니다.

```powershell
./build.ps1 -GameDir 'C:\Program Files (x86)\Steam\steamapps\common\Sephiria'
./tests/run.ps1
./package.ps1
```

다음 버전 배포 시 `AutoParry.cs`의 플러그인 버전·Version 상수·AssemblyVersion·AssemblyFileVersion을 함께 올린 뒤 빌드·검사·패키징합니다. 소스 변경을 커밋하고 `./release.ps1 -NotesFile <릴리스노트파일>`을 실행합니다. GitHub CLI 로그인과 저장소 쓰기 권한이 필요합니다. 스크립트는 DLL·update.json·설치 ZIP을 draft Release에 모두 올린 후 정식으로 공개합니다.

테스트는 업데이트의 실패 보존·다음 실행 적용·백업·다운그레이드 거부와 공격 이벤트 분류/피격 전 입력 순서를 검사합니다. 도 납도·발도 수정은 실제 게임의 무기·강화 조합별 추가 확인이 필요합니다.
